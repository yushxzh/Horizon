## [布鲁斯·施奈尔：25 年大规模监控该结束了](https://www.schneier.com/blog/archives/2026/09/25-years-of-mass-surveillance-is-enough.html) ⭐️ 9.0/10

**原标题**: [25 years of mass surveillance is enough](https://www.schneier.com/blog/archives/2026/09/25-years-of-mass-surveillance-is-enough.html)

布鲁斯·施奈尔（Bruce Schneier）发布了一篇与辛迪·科恩（Cindy Cohn）合写的文章，最初刊于 Lawfare，并转载于他的 Schneier on Security 博客，主张 9·11 之后长达 25 年的大规模监控实验已经失败，应当被撤销。该文在 Hacker News 上引发强烈反响，获得 790 分和 284 条评论。 施奈尔是安全与密码学领域最具权威的声音之一，因此他公开呼吁拆除大规模监控体系，对停滞了近二十年的政策辩论具有相当分量。其意义还在于，2001 年后建立的监控架构如今正被进一步扩展而非收缩；评论者指出 NSPM-7 将带来新一轮升级，其影响将波及所有人，而不只是安全研究者。 文章梳理了美国政府整体从定向监控手段——如针对个人的窃听、笔式记录器／陷阱与追踪令——转向大规模技术的过程，例如接入互联网骨干网，或大规模收集电话与互联网元数据。讨论中特别点名 NSPM-7，认为该机制会让大规模监控“压迫性成倍增加且无处不在”。

hackernews · Schneier on Security · 9月15日 11:26 · [社区讨论](https://news.ycombinator.com/item?id=49710883)

**背景**: 美国的大规模监控在 2001 年 9 月 11 日袭击后急剧扩张，相关项目从针对具体嫌疑人的搜查令，转向批量收集通信元数据以及在骨干网层面进行拦截。布鲁斯·施奈尔是一位密码学家与安全技术专家，以“安全是一个过程”的理念和对监控政策的长期批评而闻名；合著者辛迪·科恩是电子前沿基金会（EFF）的资深数字公民自由律师。文章首发平台 Lawfare 是关于国家安全法律的知名刊物。“笔式记录器／陷阱与追踪”指的是记录拨出与接入号码、但不记录通话内容的法律令状。

## [Typesafe.ai 推出 System One 模型与 Jev，主打类型化推理](https://typesafe.ai/blog/introducing-system-one-models-and-jev) ⭐️ 8.0/10

**原标题**: [Introducing System One Models and Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

Typesafe.ai 发布了 System One 模型与 Jev，这是一种新模型：它接收任意文本输入（包括复杂的 JSON）以及用自然语言提出的问题，并在毫秒级内返回结构化答案，例如是/否选项、多选类别、打分以及相应的概率，成本约为每百万 token 0.042 美元。该团队表示该模型使用 RLCD 训练，目标不是自由生成文本，而是直接产出代码可以使用的结构化答案。 如果其速度与成本优势属实，Jev 有望让分类、合规流程、实时决策和自主智能体的大规模运行成本远低于通用生成式大模型，从而推动整个生态走向专用化的机器对机器推理，而非一刀切的文本生成。这对需要在生产环境中获得可靠、低延迟结构化输出的开发者尤为重要。 Jev 只输出结构化结果（选项、分数、概率），因此无法替代能够生成任意代码或文本的通用生成式模型；同时该模型的官方文档被普遍认为比发布公告更清晰。社区成员还指出，将其与生成式大模型直接比较速度可能存在误导，因为两类模型执行的任务本质不同。

hackernews · albelfio · 9月15日 19:25 · [社区讨论](https://news.ycombinator.com/item?id=49717558)

**背景**: 主流大语言模型多为仅解码器（decoder-only）架构，以预测下一个 token 的方式训练，因此通过自回归方式逐字生成文本——这种方式强大但对简单任务而言既慢又相对昂贵。结构化问答则反其道而行：模型不生成自由文本，而是被约束在有限输出空间内，例如返回一个概率或类别标签，下游代码可直接使用。Typesafe.ai 将这种快速、自动、低成本的方式称为“System One”（系统一）思维，与缓慢而深思熟虑的生成方式相对，并把自身定位为“造生产工具，而非造神”，面向可靠的生产工作流。

## [互联网档案馆为 Wayback Machine 增设防护，应对爬虫流量](https://blog.archive.org/2026/09/15/an-update-on-wayback-machine-access/) ⭐️ 8.0/10

**原标题**: [An Update on Wayback Machine Access](https://blog.archive.org/2026/09/15/an-update-on-wayback-machine-access/)

在 2026 年 9 月 15 日发布的一篇博文中，互联网档案馆宣布已部署防护措施，以在遭遇多波高流量自动化访问后维持 Wayback Machine 的正常运行。博文以及评论者 Simon Willison 的转述认为，这波流量来自那些绕过原网站封锁、转而抓取存档副本的爬虫，档案馆称这种行为“令人愤慨”。 Wayback Machine 已被广泛视为互联网的核心基础设施之一，它保存了超过一万亿个网页快照，记者、研究者和维基百科编辑每天都在使用，因此持续的爬虫压力威胁的是一家以使命驱动的非营利机构，而非商业服务。若流量压力持续，档案馆可能不得不在收紧访问控制与“普遍、匿名获取知识”的既定目标之间做出取舍。 有用户反馈在某些环境（如公司网络）中会收到 HTTP 429 限流错误，而同一网址用手机却能正常打开；档案馆要求遇到错误的用户通过邮件提交细节，这引来评论者质疑：为何不直接在出错时自动记录操作系统、浏览器和 IP 地址？博文还指出，作为连锁反应，已有部分网站选择退出存档；评论者则提到，通过 Tor 匿名访问目前仍然可用，无需经过 Cloudflare 之类的中心化“看门人”。

hackernews · ChrisArchitect · 9月15日 17:52 · [社区讨论](https://news.ycombinator.com/item?id=49716176)

**背景**: 互联网档案馆是一家美国非营利数字图书馆，由 Brewster Kahle 于 1996 年创立，以“普遍获取所有知识”为使命，免费提供存档的网站、软件、音乐、影音和印刷资料。其 Wayback Machine 于 2001 年 10 月 25 日向公众开放，让用户可以查看网站过去的样子，目前保存了超过一万亿个网页快照和 99 PB 以上的数据。网络爬虫（web scraping）指用机器人或爬虫自动抓取网站数据，网站通常会封锁这类机器人，这促使部分爬虫改为从 Wayback Machine 的存档副本中获取同样的内容。

## [开发者称一个月内为 M4 Mac Mini 打造出 Linux GPU 驱动](https://codyho.dev/blog/gpu-driver/) ⭐️ 8.0/10

**原标题**: [Building a Linux GPU Driver for the M4 Mac Mini in One Month](https://codyho.dev/blog/gpu-driver/)

一位名叫 Cody Ho 的开发者发布博客，声称自己在大约一个月内为 M4 Mac Mini 做出了可用的 Linux GPU 驱动，并在过程中大量借助大语言模型来加速开发。该文章随即引发争议：有消息指出他此前已被 Asahi Linux 项目封禁，原因是他隐瞒了自己对 LLM 的大量使用，以及他曾是苹果工程师、与参与 Apple Silicon 研发的人员有直接联系这一背景。 为缺乏文档的 Apple Silicon 硬件逆向工程 GPU 驱动，历来需要专家投入数年时间，因此“一个月出成果”意味着 LLM 有可能大幅压缩这一周期、降低准入门槛。与此同时，这场争议也暴露出 AI 辅助开源工作中尚未解决的披露与伦理问题，以及来源存在争议的代码能否被 Linux 主线接受的疑问。 这一成果在技术上值得关注，但其来源却极具争议：该开发者因隐瞒 LLM 使用情况和苹果背景而被 Asahi Linux 封禁，而 Asahi Linux 据说实行严格的“禁止 AI 参与”贡献政策，因此该代码几乎不可能被合并进 Linux 内核。评论者还提出了商业机密与法律层面的担忧，提到苹果正对 OpenAI 提起诉讼，并指出所用模型的训练数据来源本身也不透明。

hackernews · ADevWithAnIdea · 9月15日 19:30 · [社区讨论](https://news.ycombinator.com/item?id=49717638)

**背景**: Asahi Linux 是一个通过逆向工程让 Apple Silicon Mac 能够运行 Linux 的社区项目；经过约两年的努力，它发布了 alpha 阶段的 GPU 驱动，并做出了全球首个针对 M1、M2 系列图形硬件的、通过一致性认证的 OpenGL ES 3.1 实现，但 M3、M4 等较新芯片仍未获得完整的 GPU 加速支持。Apple Silicon 的 GPU 直接集成在片上系统（SoC）中，与 CPU 和神经引擎共享统一内存池，而不是像独立显卡那样通过 PCIe 连接，这也是在没有官方文档的情况下为其编写驱动格外困难的原因之一。以 M4 系列为例，其 10 核 GPU 版本使用封装内的高速 LPDDR5X 内存。
